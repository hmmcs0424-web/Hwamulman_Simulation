# 빽통 PC 편집 내용 저장

관리자 모드에서 수정한 뒤 **저장**을 누르면 Firebase에 편집 데이터를 저장하고, 같은 내용의 PC 백업 HTML을 저장합니다. 첫 저장에서는 PC 파일 위치를 선택합니다. PC 저장을 취소해도 성공한 사이트 저장은 유지됩니다. 두 저장 결과는 도구 모음에 따로 표시됩니다.

- 새로고침하거나 다른 PC에서 접속하면 Firebase 저장본을 적용합니다.
- 열려 있는 화면은 서버 업데이트를 받습니다. 저장하지 않은 수정이 있는 화면은 덮어쓰지 않습니다.
- 두 관리자가 동시에 수정하면 먼저 저장한 내용을 덮어쓰지 않고 충돌을 안내합니다. PC 백업 후 새로고침해서 다시 수정하세요.
- **이전 저장본 복원**에서 버전을 선택하고 불러온 뒤 **저장**을 누르면 사이트에 반영합니다.
- 이전 저장본은 최대 10개를 보관합니다. Firestore 문서 크기를 넘지 않도록 용량이 커지면 오래된 버전부터 줄입니다.
- **PC 백업**은 사이트에 저장하지 않고 현재 수정 내용만 별도 파일로 보관합니다.
- PC 백업 HTML은 편집 데이터와 화면 원본을 포함하지만, 스크립트·스타일 등은 원래 사이트에서 불러옵니다. 완전한 오프라인 패키지는 아닙니다. 백업을 프로젝트 원본 `content.html`에 덮어쓰지 마세요.
- PC 파일 접근 권한은 브라우저를 다시 시작하면 다시 선택해야 할 수 있습니다.

## 운영 구조

편집 데이터의 기준은 Firestore `simulatorFlows/backtongPcEdits` 문서입니다. 기존 관리자 인증과 보안 규칙을 사용합니다. 문구·서식·아이콘 좌표·삽입 박스·화면별 주의사항을 저장하며, 화물·거래처 등 시뮬레이션의 연습 입력 데이터는 공유하지 않습니다.

기능 개발은 GitHub에서 관리합니다. 관리자 화면의 일반 편집은 GitHub 커밋이나 재배포가 필요 없습니다. 기능 개발로 원본 화면 구조를 크게 바꾸면 기존 편집 위치와 호환되는지 확인해야 합니다.

Firebase Hosting은 `dist`의 정적 파일만 배포합니다. Cloud Functions 및 Cloud Storage 신규 업로드 기능은 사용하지 않습니다. 무료 한도는 같은 Firebase 프로젝트의 다른 기능과 공유합니다. 첫 배포 후 Firebase 콘솔의 사용량을 확인하세요.

## 최초 배포 / 기능 업데이트

프로젝트 폴더의 터미널에서 실행합니다.

```powershell
npx firebase-tools login --reauth
npm run deploy:firebase
```

두 번째 명령은 빌드 후 `hmm-work-guide` 프로젝트의 Firebase Hosting으로 배포합니다. Firebase Hosting의 기본 주소를 사용하고, 관리자 모드 로그인 및 저장 후 새로고침을 확인한 뒤 기존 Vercel 링크를 교체하세요. 기존 Vercel 프로젝트는 이 작업에서 삭제하지 않습니다.

현재 작업 환경에서는 기존 Firebase 인증이 만료되어 배포를 완료하지 못했습니다. 소스 코드와 빌드 결과에는 수정 사항이 반영되어 있습니다.

## 검증

```powershell
node scripts/test-pc-guide-store.cjs
node scripts/test-pc-guide-browser.cjs
node scripts/test-simulator-flow-save.cjs
npm run build
```

브라우저 회귀 검사는 Windows의 Chrome 또는 Edge를 사용합니다. 다른 위치에 설치했다면 `CHROME_PATH` 환경 변수로 실행 파일을 지정하세요.
